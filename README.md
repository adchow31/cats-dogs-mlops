## Overview

A baseline CNN classifies pet images as **Cat** or **Dog**, served via a FastAPI inference service, containerized with Docker, automatically built and tested on every push (CI), automatically deployed and smoke-tested (CD), and monitored in production with Prometheus and Grafana.

| Milestone | Description | Status |
|---|---|---|
| **M1** | Model Development & Experiment Tracking (Git/DVC, baseline CNN, MLflow) | ✅ Complete |
| **M2** | Model Packaging & Containerization (FastAPI, Dockerfile) | ✅ Complete |
| **M3** | CI Pipeline (pytest, GitHub Actions, GHCR push) | ✅ Complete |
| **M4** | CD Pipeline & Deployment (Docker Compose, automated smoke tests) | ✅ Complete |
| **M5** | Monitoring, Logs & Post-Deployment Tracking (Prometheus, Grafana) | ✅ Complete |

**Final baseline model:** 91.11% validation accuracy · 99%+ confidence on live inference · 100% accuracy on post-deployment sample tracking.

## Tech Stack

- **Model:** PyTorch (custom CNN), trained on CPU
- **Experiment Tracking:** MLflow (params, metrics, confusion matrix, loss curves)
- **Data & Model Versioning:** Git + DVC (local remote)
- **Inference Service:** FastAPI + Uvicorn
- **Containerization:** Docker, GitHub Container Registry (GHCR)
- **CI:** GitHub Actions — test, build, push
- **CD:** GitHub Actions + Docker Compose — deploy, smoke test
- **Monitoring:** Prometheus (metrics scraping) + Grafana (dashboards), structured application logging

## Getting Started

### Prerequisites

- Python 3.13
- Docker Desktop
- (Optional) A Kaggle account, if re-downloading the dataset via `kagglehub`

### 1. Clone and set up

```bash
git clone https://github.com/adchow31/cats-dogs-mlops.git
cd cats-dogs-mlops
pip install -r requirements.txt
```

### 2. Train the model (optional — a trained checkpoint is already included)

Open and run `notebooks/01_train_baseline.ipynb` top to bottom. This will:
- Download the Cats vs Dogs dataset via `kagglehub`
- Split it into train/val/test (80/10/10)
- Train the baseline CNN for 10 epochs
- Log all runs, metrics, and artifacts to MLflow
- Save the trained model to `models/baseline_cnn.pt`

View experiment tracking locally:
```bash
mlflow ui --port 5000
# open http://localhost:5000
```

### 3. Run the API locally

```bash
uvicorn app.main:app --reload --port 8000
```

Visit `http://localhost:8000/docs` for the interactive Swagger UI, or test directly:

```bash
curl http://localhost:8000/health

curl -X POST http://localhost:8000/predict \
  -F "file=@path/to/image.jpg"
```

Example response:
```json
{"label": "Cat", "confidence": 0.9917, "probabilities": {"Cat": 0.9917, "Dog": 0.0083}}
```

### 4. Run with Docker

```bash
docker build -t cats-dogs-classifier:v1 .
docker run -d -p 8000:8000 --name cats-dogs-api cats-dogs-classifier:v1
curl http://localhost:8000/health
```

### 5. Run with Docker Compose (matches CD deployment)

```bash
docker compose pull   # pulls ghcr.io/adchow31/cats-dogs-mlops:latest
docker compose up -d
docker compose ps
```

## CI/CD Pipeline

**CI** (`.github/workflows/ci.yml`) runs on every push to `main`:
1. Checkout → install dependencies → run `pytest`
2. Build the Docker image
3. Push to `ghcr.io/adchow31/cats-dogs-mlops:latest`

**CD** (`.github/workflows/cd.yml`) triggers automatically after a successful CI run:
1. Pull the newly published image
2. Deploy via Docker Compose
3. Run `scripts/smoke_test.sh` against the live `/health` and `/predict` endpoints
4. Fail the pipeline if either check does not return HTTP 200

## Monitoring

The API exposes a Prometheus-compatible `/metrics` endpoint (via `prometheus-fastapi-instrumentator`), tracking request counts and latency per route. Structured logs record prediction outcomes (label, confidence, filename, latency) — **the uploaded image content itself is never logged.**

```bash
# Prometheus (scrapes the API every 10s)
docker compose up -d prometheus
# open http://localhost:9091 → Status → Targets

# Post-deployment accuracy check against a small labeled sample batch
python monitoring/metrics.py
```
